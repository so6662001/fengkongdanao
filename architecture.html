PULL实时查询 API
ERP 页面加载或用户操作时同步调用，P95 142ms。用于报价风控校验、客户风险画像、市场对标价、采购风控校验、配货建议。
PUSH事件推送 Webhook
客户风险等级变化、新增失信事件、库存抛压预警、供应商告警时主动推送 ERP，ERP 落库后列表页直接显示，无需每次实时查询。
EMBED嵌入式组件 SDK
一行 JS 标签在 ERP 页面渲染风险徽章与风险卡片，ERP 后端零改造，适合老系统快速上线。
WRITE结果回写 API
业务员在 ERP 里的采纳 / 否决与最终业务结果直接回写风控大脑，不用再登录风控系统补填，决策回写率由 41% 提升至 92.4%。
四个落地场景：销售员报价时看到客户风险与市场对标价；采购员采购配货时看到平台货源体量、同业报价与供货商风险； 财务查应收时每行直接带风险等级与失信事件；管理者看经营报表时同屏看到风险总览与行业市场风险，并能直接用大白话追问。

业务执行与预警层
把 AI 结论嵌进真实业务流程节点，形成可追踪的闭环
查看业务流程
风险分级推送
低 / 中风险推送对应负责人；高风险直达高管。推送渠道：站内 + 企微 + 短信。
  • 低风险 → 业务员 / 客服
  • 中风险 → 部门负责人
  • 高风险 → 总经理 + 财务总监
采购审批节点风控增强
提交采购申请时，不再只看自有库存水位，同时拉取：
  • 平台该品类整体挂牌货源体量
  • 同业报价水平
  • 品类行情指数与成交情绪
→ 输出「市场货源泛滥，不建议大批量采购」或「市场货源紧缺，可适度备货」，从源头减少积压。
风险处置工单闭环
AI 给出建议 → 业务人员填写采纳 / 部分采纳 / 否决、执行动作、最终业务结果 → 全部回流系统沉淀案例。
  • 决策留痕：谁、什么时候、为什么
  • 结果回填：是否滞销 / 是否坏账
上游供应商风险告警
长期合作上游供货商一旦被失信 API 检测到重大风险事件，立即推送供应链风险预警给采购负责人，提示断货与预付款损失风险。
发票风控四道闸口 查看详情
把票税风险卡在业务节点上：供应商准入 → 付款前 → 勾选抵扣前 → 销项开票前，四道闸口全部开放 API 给 ERP 调用，统一为「提示 + 转审批」不强阻断。
  • 付款前是价值最高的一道 —— 款未付、票未抵扣，止损窗口最大
  • 配套证据链一键归档：固化付款当日的供应商资质与查验快照，这是善意取得抗辩的核心
  • 异常凭证应急处置：自动定位关联业务、测算进项转出与滞纳金、评估举证条件

模型详情推理实录
引擎 A · 量化预测模型（特征集大幅扩容）
库存呆滞 & 跌价预测模型 特征扩容
原来只依靠内部出库历史判断周转速度，现在叠加整个商圈的供需挂牌热度。
  • 平台同规格商户挂牌量环比变化
  • 挂牌均价走势 / 与成本价价差
  • 货源撤牌速率
  • 平台行情指数波动率
输出：呆滞概率 · 预估潜在浮亏 · 市场抛压等级 · 短期行情情绪等级
应收坏账概率预测模型 特征扩容
  • 失信检测 API 实时风险事件（大模型判定严重等级，区分「小额官司」与「大额执行 / 资金链断裂」）
  • 若客户同为平台商户：其挂牌抛售行为变化作为隐性资金紧张信号
  • 逾期账龄、回款准时率、授信使用率
  • 沟通纪要拖延话术频次
供应链风险预测子模型
本次新增。为采购决策增加一层上游风险提示。
  • 上游核心供货商失信风险
  • 上游商家大规模抛货带来的采购踩坑风险
  • 供货集中度 × 在手未交付订单敞口
引擎 B · 三大 Agent 智能体集群（全部升级推理输入源）
① 库存风控智能体 升级最大
同时读取全平台同规格货源挂牌热度、大量商户报价变化、自有平台行情指数，不再只看自家库存和外部公开行情。
典型输出：多套处置路径（分批降价出清 / 搭配热销货搭售 / 暂停该品类新增采购），并分别测算资金占用与预估亏损。
② 客户应收风控智能体
除内部聊天语义风险挖掘外，定时调用失信 API 扫描全部赊销客户；抓取新增立案、被执行等事件后自动解读影响力并上调风险等级。
若客户同时是平台入驻商户，额外结合其抛售货源行为综合研判资金压力。
③ 经营全局风控中枢智能体
跨链条连锁推演能力升级。
示例：平台建材钢材大量商户抛售 → 判断下游地产需求走弱 → 自动筛查客户清单中所有地产 / 工程类客户 → 批量上调坏账预警等级，提前预警系统性应收风险。
选型策略（不变）：前期 RAG 知识库 + Prompt 工程快速上线；沉淀足量自有业务案例 + 平台行业案例之后，再开展 LoRA 微调，投入产出比最优。不要一开始就直接训练专属大模型。

关键避坑要点

与自有平台联动之后需要额外注意
① 区分定位
AI 依然只是决策辅助，不自动下达业务指令，最终决策权留给人。系统价值是更早发现风险、提供更多维度信息、推演多套方案。
② 数据治理优先级
必须先完成钢材规格编码标准化。内部 ERP 规格与平台商家上传规格口径不一致，若没有标准化映射，海量商家报价数据无法正确匹配到自有库存 SKU，整个新增能力无法生效 —— 这是项目最关键前置工作。
③ 失信 API 调用策略
不做无限制高频全量轮询。采用「常规客户定时巡检、高风险客户高频扫描」策略，控制接口调用成本。
④ 不要一开始就训练专属大模型
优先 RAG + 提示词工程快速落地，先跑通业务闭环，沉淀真实业务案例之后再微调，投入产出比最高。
