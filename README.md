# 钢铁行业 AI 风控大脑 · 高保真原型

面向钢贸企业的 AI 风控体系高保真 HTML 原型。在原有「内部库存滞销 + 应收欠款坏账」风控体系基础上，接入自有钢铁资源平台三大核心数据，形成 **「内部经营数据 + 行业全域市场数据」双驱动**风控体系，并保留业务回流、持续迭代的数据飞轮闭环。

## 快速开始

纯静态页面，零构建、零外部依赖（图表为自研 SVG 实现，**离线可直接打开**）。

```bash
# 方式一：直接用浏览器打开
open index.html

# 方式二：本地起一个静态服务（推荐，避免个别浏览器的 file:// 限制）
python3 -m http.server 8080
# 然后访问 http://localhost:8080
```

建议浏览器窗口宽度 ≥ 1440px 以获得最佳信息密度。

> **页面看不到某个新增入口时**：左侧导航是由 `assets/js/app.js` 动态渲染的，浏览器如果缓存了旧版 JS，新页面的入口就不会出现。所有资源引用已带版本号（`?v=20260817`），正常刷新即可；若仍未更新，用 `Ctrl/Cmd + Shift + R` 硬刷新一次。

## 本次升级的核心增量

三大自有平台数据源接入（页面中以 `NEW` / 青色标识）：

1. **500+ 商家每日货源价格数据流** —— 挂牌货源、规格材质、挂牌单价、挂牌余量、上新/撤牌动态，按「规格-区域-时间」时序存储；热门规格小时级同步，长尾规格每日全量快照。
2. **平台行情指数 API** —— 分品类行情指数、区域热度指数、成交情绪指数，作为贴合自身商圈的先行指标优先入模。
3. **企业失信风险检测 API** —— 两层调用：下游赊销客户征信巡检 + 平台入驻商户（上游供货商）风险监控。

由此新增的能力：市场抛压等级与短期行情情绪等级输出、供应链风险预测子模型、采购审批节点的市场供需风控、上游供应商风险告警、行业市场风险总览面板。

## 与 ERP 的双向集成

数据从 ERP 来，风险结论还要回到 ERP 去 —— 业务人员不用切换系统，风险信息出现在他本来就在看的那个页面上。

- **上行（ERP → 风控大脑）**：库存台账、订单、应收、授信、票据批量同步，加上业务事件实时上送接口 `POST /v1/ingest/events`。
- **下行（风控大脑 → ERP）**四种方式：
  - 实时查询 API（Pull）—— 报价风控校验、客户风险画像、市场对标价、采购风控校验、配货建议，P95 142ms；
  - 事件推送 Webhook（Push）—— 客户风险等级变化、新增失信事件、库存抛压预警、供应商告警；
  - 嵌入式组件 SDK（Embed）—— 一行 JS 标签渲染风险徽章与风险卡片，ERP 后端零改造；
  - 结果回写 API（Write）—— 业务员在 ERP 里的采纳 / 否决与最终业务结果直接回写，喂给数据飞轮。

四个落地场景（见 `erp-embed.html`）：销售员报价时看到客户风险与市场对标价；采购员采购配货时看到平台货源体量、同业报价与供货商风险，并知道该优先出哪个批次；财务查应收时每行直接带风险等级、坏账概率与最新失信事件；管理者看经营报表时同屏看到风险总览与行业市场风险，并能直接用大白话追问。

一条贯穿的设计原则：**风控接口是 ERP 的旁路增强，不是主链路**。任何超时、异常、限流，ERP 都必须能继续把单开出去，只是不显示风险信息或显示上次缓存结果；高风险也只是提示 + 转审批，不自动拦单。

## 采购智能定价预警（钢铁大宗行情三阶梯）

钢材是大宗商品，判断行情不能套用通用商品的百分比尺度 —— 采购员脑子里是「今天跌了 30 块」而不是「跌了 0.86%」。所以这套模型有三个钢铁特有的设定：

1. **主尺度是元/吨**，不是百分比；
2. **必看期货盘面与基差**（螺纹 RB、热卷 HC、铁矿 I、焦炭 J 有主力合约，盘面领先现货半天到一天；基差 = 现货 − 期货，升水过高意味着现货有补跌压力）；
3. **成本支撑按配比算**：长流程 = 铁矿×1.6 + 焦炭×0.45 + 辅料加工，短流程 = 废钢×1.05 + 电费 + 电极合金；**电炉平电成本是螺纹钢的价格地板**，跌破后电炉厂减产。

| 阶段 | 门槛（3 日累计） | 市场特征 | 采购动作 |
| --- | --- | --- | --- |
| 平稳期 | ≤ ±30 元/吨 | 报价集中，钢厂旬价基本持平 | 钢厂订货 70% + 市场 30%，备货 10~15 天，限价取基价 −10 |
| 线上波动期 | ±30 ~ ±80 元/吨 | **线上同规格报价开始分化**，极差拉大到 30~60 元，商户日均调价 1~3 次 | 钢厂额度用一半分旬打款，市场端分批点价，备货 5~8 天，限价取平台 25 分位 |
| 加速上涨期 | > +80 元/吨 | 货源收缩、撤牌率上升、钢厂连续上调并限量接单 | 用足钢厂额度争取保价协议，备货 20~30 天，可接受基价 +30，买入保值 |
| 加速下跌期 | > −80 元/吨 | 商户集中抛售、撤牌率骤降、钢厂连续下调并让利结算 | 停止钢厂预订只走市场现货背靠背，预付降为 0，限价改用**期货主力 + 常态基差 − 安全垫**，库存卖出保值 30%~50% |

判定用 5 大类 11 项指标加权：现货价格（3 日累计涨跌 16%、单日最大波动 8%）、期货盘面（主力 3 日涨跌 14%、基差偏离常态 12%）、钢厂政策（旬度调价 12%、结算追补让利 6%）、线上报价（挂牌商户数 3 日变化 10%、同规格报价极差 8%、日均调价频次 6%）、供需库存（社会库存周环比 5%、表观消费周环比 3%）。得分 <30 平稳、30~62 线上波动、≥62 加速。

另有六条**一票否决/强制修正规则**（指标算不出来但必须遵守的行业经验）：钢厂单日调价 >100 元强制判加速期、期货封停强制判加速期、跌破电炉成本改判「可分批试探性建仓」、现货深度贴水降一级警示、旺季/冬储窗口放宽备货天数 50%、主产区限产落地时下跌判定降权。

**定价落到规格与材质**：采购限价 = 阶段基准价 + 规格差价 + 材质升水 + 钢厂品牌溢价 + 区域价差。例如 HRB400E Φ32 永钢杭州 = 3,406（RB2610 主力 3,386 + 常态基差 40 − 安全垫 20）+ 90（Φ32 规格差价）+ 0（HRB400E 基准）− 10（永钢）− 20（杭州）= **3,466**。

规格差价本身就是资源松紧的信号：同为螺纹钢 HRB400E，主流 Φ16~Φ25 三日跌 92~98 元已进加速下跌期，而 **Φ12、Φ14 细规格与 Φ28、Φ32 大规格只跌 64~86 元，仍在线上波动期** —— 因为这些规格产量少、需求刚性，规格差价反而在扩大（Φ32 由 62 扩到 90 元，处 30 日 88 分位）。只看品类指数一刀切停采，Φ32 会断供影响交付；照常备货，Φ20 就在下跌通道里越买越亏。

## 发票风险管控

钢贸企业最大的现实敞口不是自己虚开，而是**善意取得虚开专票** —— 上游走逃失联，已抵扣的进项被要求转出，一笔就能吃掉几年利润。所以整套设计的重心是把风险卡在**付款前**和**勾选抵扣前**这两道闸口。

**四大风险域**（60 条规则）：发票合规（真伪查验、抬头四要素、跨主体查重、红冲预警、税率与税收分类编码、计量单位、跨期开票）、税务指标异常（税负率、三表四方比对、进项集中度、留抵与库存背离）、业务真实性（四流六单勾稽、资金回流、过磅单缺失、运输合理性）、信用与欺诈（走逃失联、异常凭证、空壳画像、变名开票、循环开票环路）。

**四道闸口，全部开放 API 给 ERP 调用**，统一为「提示 + 转审批」，不强阻断，保留申诉与补材料通道：

| 闸口 | 时机 | 接口 |
| --- | --- | --- |
| 供应商准入 | 新增供应商 / 首次开票前 | `POST /v1/invoice/gate/supplier-access` |
| **付款前**（最关键） | 财务发起付款时 | `POST /v1/invoice/gate/pre-payment` |
| 勾选抵扣前 | 月度用途确认 / 申报前 | `POST /v1/invoice/gate/pre-deduction` |
| 销项开票前 | 我方对外开具数电票前 | `POST /v1/invoice/gate/pre-issuing` |

四道闸口返回结构统一（`decision` / `blocked` / `appealable`），ERP 侧只需按这三个字段统一渲染，无需为每道闸口写不同逻辑。

**钢贸口径的几处关键设定**（均为租户可配置项）：

- **税负率基线 0.3%~0.8%**，按主体分别设置。钢贸低毛利高流水，套用制造业 2%~3% 会导致全量误报。真正有效的判据是环比波动与**和毛利率的背离**（毛利 3% 但税负 0.1% → 疑似虚开进项；毛利 1% 但税负 2% → 疑似进项不足）。
- **红冲率建 ±2σ 基线不设死阈值**：过磅差、质量异议、退货在钢贸是常态，红冲本身是正常业务动作。
- **票货容差按品种**：棒材 ±3%、板卷 ±1.5%、型材 ±2.5%、管材 ±2%。理计磅计差 1.5%~3% 是钢材固有特性，容差过严会每笔报警。
- **无票采购单独归为「票源缺口」台账**，不判为风险：废钢、个体运输本来就开不出票。
- **多主体模式可开关**：开启后做跨主体发票查重、关联交易识别与合并口径税负率。

**证据链一键归档**是这个模块产品价值最高的一块：稽查时要证明的是「我付款那天查过，他当时是正常纳税人、四流齐备」，所以证据包固化的是**付款当日的快照**（营业执照、纳税信用等级、失信查询结果、四道闸口校验结论），而不是事后补的材料 —— 事后供应商早已失联，什么都证明不了。

## 说明

- 页面中所有数值均为**演示用模拟数据**，字段口径按真实钢贸 ERP 与资源平台设计，并做了跨页面交叉一致（如各品类货值合计 = 库存总货值、高风险客户应收合计 = 坏账高风险敞口）。
- 原型强调一个定位：**AI 只做决策辅助，不自动下达业务指令**。所有处置建议都需要人工在工单中填写采纳 / 部分采纳 / 否决与执行动作，结果回填后归档为案例。
