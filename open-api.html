双向集成架构

上行：ERP 业务数据入湖；下行：风险结论回流 ERP 业务界面
上行 5 类下行 4 种方式
PULL实时查询 API
ERP 页面加载 / 用户操作时同步调用，毫秒级返回风险结论。适合报价、采购申请、客户详情等需要当场看到结论的场景。
  • P95 < 200ms，超时 800ms 自动降级
  • 结果带 5 分钟缓存标记，避免重复调用
PUSH事件推送 Webhook
风险等级变化、新增失信事件、抛压预警时，风控大脑主动推送给 ERP，ERP 落库后可在列表页直接展示，无需每次实时查询。
  • HMAC-SHA256 签名 + 事件幂等 ID
  • 失败指数退避重试 5 次（1m/5m/30m/2h/6h）
EMBED嵌入式组件 SDK
一行 JS 标签即可在 ERP 页面渲染风险徽章 / 风险卡片，ERP 后端零改造，适合快速上线与老系统。
  • Shadow DOM 隔离样式，不污染 ERP
  • 支持深浅两套主题自动适配
WRITE结果回写 API
业务员在 ERP 里的采纳 / 否决、实际执行动作、最终业务结果回写风控大脑，直接喂给数据飞轮，无需业务员再登录风控系统填一遍。
  • 决策回填 + 业务结果回填
  • 回写即进入案例池与微调样本池

鉴权与安全

OAuth2 + 签名双保险
鉴权方式OAuth2 client_credentials
Token 有效期7200s（自动续期）
请求签名HMAC-SHA256（防篡改）
传输HTTPS / TLS 1.2+
访问控制IP 白名单 + 接口级权限
数据脱敏按角色返回字段
ERP 不同角色看到的字段不同：业务员只看到风险等级与建议动作，不返回坏账概率明细与失信原文；财务与管理者返回完整字段。由接口级权限控制，不在前端做隐藏。

SLA 与降级策略

风控不可用时绝不阻断业务
最重要的一条原则：风控接口是 ERP 的旁路增强，不是主链路。任何超时、异常、限流，ERP 都必须能继续把单开出去 —— 只是不显示风险信息或显示上次缓存结果。
异常场景ERP 侧行为提示
响应超时 >800ms用本地缓存的上次风险等级数据可能延迟
接口 5xx跳过风控展示，业务正常进行风控暂不可用
触发限流 429降级为 Webhook 落库数据非实时
客户未匹配到主数据正常放行并记录待映射新客户待评估
高风险且强管控开关开启仅提示 + 需上级审批，不自动拦单需审批

ERP 接入实施步骤

从申请凭证到全场景上线
① 申请接入凭证与联调环境 0.5 天
分配 app_id / app_secret、配置 IP 白名单与接口权限，开通 sandbox 环境（返回构造数据，可反复调试）。
② 打通主数据映射 最关键
ERP 客户编码 ↔ 统一社会信用代码；ERP 物料编码 ↔ 平台标准规格编码。这一步没做好，后面所有接口返回的都是空结果，与规格标准化是同一件事的两端。
③ 先接「只读展示」类接口
客户风险画像、市场对标价先上线，纯展示不影响流程，风险最低，业务员当天就能看到价值。
④ 再接「流程校验」类接口
报价风控校验、采购风控校验接入单据提交流程，配合灰度开关，先只提示不拦截，跑两周确认误报率后再决定是否开启审批管控。
⑤ 打通 Webhook 与结果回写
风险等级变化推送 ERP 落库；ERP 里的采纳 / 否决与业务结果回写风控大脑，闭合数据飞轮。
各场景接入优先级建议
ERP 场景接入方式改造量业务价值建议顺序
客户 / 应收查询页嵌入式组件极小高1
销售报价 / 订单页查询 API + 组件中高2
采购申请 / 配货页查询 API中高3
经营报表 / 驾驶舱汇总 API + 问答小中4
审批流 / 消息中心Webhook较大中5
为什么先接客户/应收页：只需在客户名称旁挂一个组件，ERP 几乎不用改代码，业务员立刻能在自己每天都看的页面上看到风险，接受度最高，也最容易证明价值。
为什么报价校验先只提示不拦截：拦单会直接影响成交，一旦误报业务会强烈抵触。先跑两周观察误报率与采纳率，数据说话之后再谈管控强度。
